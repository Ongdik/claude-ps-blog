# claude-ps-blog

알고리즘 풀이(PS)를 티스토리용 한국어 기술 블로그 글로 정리하는 Claude 스킬이다.

[![test](https://github.com/Ongdik/claude-ps-blog/actions/workflows/test.yml/badge.svg)](https://github.com/Ongdik/claude-ps-blog/actions/workflows/test.yml)
![license](https://img.shields.io/badge/license-MIT-blue)

AI에게 풀이 글을 맡기면 비슷한 글이 나온다. "~에 대해 알아보겠습니다"로 시작하고, 정답 코드를 해설서처럼 설명하고, "자료구조 선택의 중요성을 깨달을 수 있었다" 같은 목록으로 끝난다. 정작 내가 어디서 막혔고 무엇을 알게 돼서 풀었는지는 빠진다.

이 스킬은 글을 **내 생각의 흐름**대로, 짧게 쓴다.

1. **흐름**: 문제 원문 → 생각한 흐름 → 틀린 코드 → 막힌 지점 → 정답 코드 → 돌아보며. GPT나 Claude에 물어본 대화 기록을 주면 질문 하나하나를 막힌 지점으로 읽고 그 순서대로 쓴다. 묻고 답한 과정은 빼고 알게 된 내용만 "찾아보니 ~한다"로 쓴다.
2. **깊이**: 내가 이해한 만큼만 쓴다. AI 답변의 계산 과정이나 수식은 옮기지 않고, 아직 모르는 건 "추후 알아보려고 한다"로 남긴다. 번호 목록이나 `->` 같은 메모 형태도 그대로 살린다.
3. **내용**: 말하지 않은 경험, 막힘, 감정, 측정값을 지어내지 않는다.
4. **문체**: 한국어 AI 글에서 자주 보이는 표현을 목록으로 관리하고, 발행 전에 스크립트로 검사한다.

## 글 모양

```markdown
# [백준 1920] 수 찾기

## 문제
> 문제 원문 그대로

## 생각한 흐름
- 풀기 전 계획 메모 그대로

## 틀린 코드
틀린 코드 전체 + 틀린 부분 개조식

## (막힌 내용을 쓴 소제목)
찾아보니 ~한다.

## 정답 코드
정답 코드 전체

## 돌아보며
**왜 막혔을까**
- 막힌 이유 개조식

다음엔 무엇부터 볼지 서술.
```

- 제목에는 문제 이름만 쓴다. 막힌 내용은 돌아보며의 「왜 막혔을까」로 간다.
- 문제는 요약하지 않고 원문을 그대로 넣는다. 원문은 직접 붙여 넣는다. 플랫폼·번호·제목만 주면 출처 링크와 원문 자리를 만들어 둔다.
- 「왜 막혔을까」는 "같은 방식으로 민 점"처럼 명사형으로 끝낸다.
- 코드는 틀린 코드와 정답 코드를 각각 전체로 넣는다. 고친 부분만 조각조각 넣지 않는다.

## 차이 예시

리스트 `in`으로 풀었다가 시간 초과, `set`으로 바꿔 통과한 경우의 막힌 지점과 돌아보며.

**스킬 없이**

> ## 시간 초과의 원인 분석
> 리스트의 in 연산은 선형 탐색으로 동작하므로 O(N)의 시간이 소요됩니다. 따라서 해시 기반 자료구조인 set을 활용하여 개선할 필요가 있다고 판단했습니다.
>
> ## 정리
> - 자료구조 선택의 중요성을 깨달을 수 있었다.
> - 좋은 계기가 되었다.

**스킬 적용**

> ## 리스트 in이 느렸던 이유
> 반복문이 하나밖에 없어서 왜 느린지 감이 안 왔다. 찾아보니 리스트에서 `in`은 앞에서부터 하나씩 비교한다. 눈에 보이는 반복문은 하나지만 `in` 안에 반복문이 하나 더 숨어 있었던 거다.
>
> ## 돌아보며
> **왜 막혔을까**
>
> - 반복문이 하나니까 괜찮겠지 하고, `in`이 안에서 하나씩 비교한다는 걸 생각하지 않은 점
> - 같은 자료에서 10만 번을 찾는데 리스트를 그대로 쓴 점
>
> 다음부터는 같은 자료에서 여러 번 찾는 코드가 보이면 `in` 앞에 있는 게 리스트인지 먼저 확인해 볼 생각이다.

첫 번째는 AI 답변을 옮긴 해설이고, 어떤 문제에 붙여도 말이 되는 정리로 끝난다. 두 번째는 무엇을 몰랐는지에서 출발하고, 왜 막혔는지를 먼저 짚은 뒤 이 문제에서만 나올 수 있는 말로 끝난다.

## 구성

```text
skills/ps-solution-blog/
├── SKILL.md            글 구성, 원칙, 문체 규칙, 발행 전 검사 절차
├── banned-phrases.md   금지·주의 표현 목록 (검사 스크립트가 이 표를 읽음)
├── voice-exemplars.md  나쁜 예 / 좋은 예 비교
└── scripts/check.py    발행 전 기계 검사
```

| 파일 | 내용 |
|---|---|
| `SKILL.md` | 대화 기록에서 막힌 지점을 뽑는 방법, 문제 원문 → 생각한 흐름 → 틀린 코드 → 막힌 지점 → 정답 코드 → 돌아보며 글 구성, 사용자가 이해한 깊이만큼 쓰는 기준, 발행 전 검사 (기계 검사, 의미 검사 5항목, 채팅 보고) |
| `banned-phrases.md` | 도입·마무리 상투구, 과장, 반전·수사, 메타 서술·번역투("판단했다" 포함), 자기비하, 정리·회고 상투구, 과한 설명(계산 과정·연산량), 형식 8개 분류. 항목마다 `금지` / `주의` 수준과 대안 |
| `voice-exemplars.md` | 글 깊이(6중 for문 예시), 그리고 2차원 바람 문제로 제목, 문제, 생각한 흐름, 틀린 코드, 막힌 지점, 정답 코드, 돌아보며를 섹션별로 비교 |
| `scripts/check.py` | 표현 패턴 검사와 구조 검사 (코드 블록 언어 태그, 제목 개수·단계, 문체 혼용, 굵은 글씨 과다, 질문형 소제목, 목록으로만 된 정리, 수식 블록, 제목 부제). 코드 블록과 인용(문제 원문) 안은 검사하지 않음 |

## 설치

### claude.ai (채팅, Claude 문서)

1. [Releases](https://github.com/Ongdik/claude-ps-blog/releases)에서 `ps-solution-blog.zip`을 받는다.
2. claude.ai의 스킬 설정에서 zip을 업로드한다. 같은 이름의 스킬이 있으면 교체한다.

Release가 아직 없으면 직접 묶는다.

```bash
cd skills && zip -r ../ps-solution-blog.zip ps-solution-blog -x '*/__pycache__/*'
```

### Claude Code (플러그인)

```text
/plugin marketplace add Ongdik/claude-ps-blog
/plugin install ps-solution-blog@claude-ps-blog
```

### Claude Code (심볼릭 링크)

```bash
git clone https://github.com/Ongdik/claude-ps-blog.git
ln -s "$(pwd)/claude-ps-blog/skills/ps-solution-blog" ~/.claude/skills/ps-solution-blog
```

## 사용

### 기본 흐름

스킬은 한 번 등록하면 모든 대화에서 켜져 있다. 대화마다 다시 넣을 필요는 없다.

1. **문제 하나에 새 대화 하나를 연다.** 여러 문제를 한 대화에서 풀면 글의 흐름이 섞인다.
2. **그 대화에서 평소처럼 풀고 질문한다.** 막힌 부분을 묻고, 답을 듣고, 코드를 고친다. 이 대화가 그대로 글의 재료가 된다.
3. **최종 코드가 나오면 같은 대화에서 글을 요청한다.** 질문한 순서가 글의 흐름이 되므로 대화 기록을 따로 붙여 넣을 필요가 없다.
4. **Claude 문서로 나온 글을 Markdown으로 내보내 티스토리에 붙여 넣는다.** 검사 결과는 본문이 아니라 채팅에 따로 보고된다.

스킬이 적용되지 않는 것 같으면 "ps-solution-blog 스킬로 써줘"처럼 이름을 직접 말한다.

### 요청할 때 한두 줄 덧붙이기

대화만 보고는 Claude가 설명한 것 중 어디까지를 실제로 이해했는지 알 수 없다. 글을 요청할 때 아래 내용을 한두 줄 덧붙이면 "이해한 만큼만" 규칙이 정확하게 적용된다.

- 이해한 것과 아직 모르는 것
- 길게 설명들었지만 흘려들은 부분 (빼 달라고 한다)
- 틀린 코드로 넣을 버전과 최종 정답 코드
- 문제 원문 (Claude가 웹에서 가져와 옮기지 않으므로 직접 붙여 넣는다. 안 주면 링크와 빈 자리만 만든다)
- 나중에 알아볼 것

```text
블로그 글 써줘. 누적합 아이디어는 이해했는데 히스토그램은 아직 모르니까
나중에 볼 거라고만 써줘. 결국 제출한 건 4중 for문 버전이야.
```

### 다른 곳에서 풀었을 때

GPT 등 다른 곳에서 풀었다면 새 대화를 열고 문제, 처음 코드, 최종 코드, 대화 기록을 붙여 넣은 뒤 요청한다. 대화 기록이 없으면 어디서 막혔는지 몇 줄만 적어도 된다.

```text
백준 1920 풀었어. 처음엔 리스트 in으로 했다가 시간 초과 났고,
왜 느린지 물어보니까 하나씩 비교한대서 set으로 바꿨어. 코드 두 개 붙일게.
```

코드만 주면 어디서 막혔는지 한 번 물어본 뒤에 쓴다.

### 이미 쓴 글 검사

```text
이 글 발행 전에 검사해줘.
```

글을 다시 쓰지 않고, 걸린 표현과 고친 문장만 짝지어 보여준다.

### Claude Code에서 쓸 때

흐름은 같고, 결과가 Claude 문서 대신 `[플랫폼]-[번호]-[문제이름].md` 파일로 저장된다.

### 검사 스크립트만 쓰기

Python 3.10 이상, 외부 패키지 없음.

```bash
python3 skills/ps-solution-blog/scripts/check.py 글.md
python3 skills/ps-solution-blog/scripts/check.py 글.md --strict   # 주의 항목도 실패 처리
python3 skills/ps-solution-blog/scripts/check.py 글.md --json
```

```text
검사 대상: 글.md
결과: 금지 2건, 주의 1건

[금지]
  A01 3행: 알아보겠습니다
      예: 이분 탐색에 대해 알아보겠습니다 → 바로 본론을 쓴다
  S01 11행: ```
      코드 블록에 언어 태그를 붙인다 (예: ```python)

[주의]
  D03 5행: 라고 할 수 있습니다
      예: 핵심 아이디어라고 할 수 있습니다 → 핵심 아이디어다
```

종료 코드는 0(통과), 1(금지 발견), 2(실행 오류)다.
